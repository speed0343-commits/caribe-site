# 카리브무역 B2B 카탈로그 — 작업 안내 (Claude 용)

주식회사 카리브무역의 **B2B(정비업체·카센터·부품 판매업체) 전용** 수입차 브레이크 디스크 카탈로그입니다.
A4 세로 HTML 페이지를 데이터로 자동 구성하고, 같은 화면을 PDF로 저장합니다. **홈페이지와는 별개**입니다.

## 폴더 구조

```
(맨 위)                    ← 저장소 또는 전달용 묶음(caribe-catalog/)의 맨 위
├─ catalog-data.js         상품 60종·적용 차종·가격 (자동 생성 파일, 직접 고치지 않음)
├─ data.js, core.js        제조사 한글명·공통 함수 (홈페이지와 공용 — 카탈로그 작업으로 고치지 않음)
├─ data/research-papers.js, literature-measurements.js, test-plan.js   기술 자료(논문·특허) 데이터
├─ assets/, images/        로고·가공 사진·표지 디스크 이미지
└─ catalog/
   ├─ index.html           화면 틀 (도구 막대 + 스크립트 순서)
   ├─ catalog.js           ★ 모든 쪽의 구성과 문구 (아래 '쪽 구성' 참고)
   ├─ catalog.css          ★ 디자인 (색은 맨 위 :root 토큰)
   ├─ editor.js            화면에서 글자를 고치는 수정 모드 (edits.json 저장)
   ├─ edits.json           사람이 수정 모드로 고친 내용 (있을 때만)
   ├─ server.js            미리보기 서버 → http://localhost:4000
   ├─ build-pdf.js         PDF 만들기 → catalog/caribe-catalog.pdf
   ├─ make-bundle.py       전달용 zip 만들기 → catalog/dist/caribe-catalog-source.zip
   ├─ brand/               logo-silver.png(표지용 로고), qr-site.svg(홈페이지 QR)
   └─ photos/              base-disc.png(대표 제품 이미지), photos.js(품번별 실제 사진 등록)
```

## 쪽 구성 (catalog.js 안의 순서, 현재 A4 35쪽)

| 주석 표시 | 쪽 | 내용 |
| --- | --- | --- |
| `1. 표지` | 1 | 실버 로고 + "주식회사 카리브무역", 제목, 통계 4개 |
| `2. 회사 소개 + 목차` | 2 | 사업 분야, 핵심 경쟁력, 회사 개요, 취급 차종·브랜드, 목차(자동) |
| `3. 주문 안내` | 3 | 거래처 주문 안내, 가격 및 거래 조건, 주문 절차, 제품 페이지 보는 법 |
| `3-1. A/S · 교환·반품 안내` | 4 | 품목별 A/S 기간 표, 공통 유의사항 7개, 브레이크 디스크 A/S·반품 기준 7개 |
| `4. 카오스 가공` | 5 | 타입 사진 4장, 가공비 표(데이터), 고객 제안 가이드 |
| `4-1. 연구 자료` | 6–7 | 기술 자료 ①(GM 특허 등) ②(한국자동차공학회 논문 표, 자체 시험 계획) |
| `5. 상품 카드` | 8–17 | 제품 60종, 한 쪽에 6개 |
| `6. 차종별 색인` | 18–32 | 제조사별로 쪽을 나눔. 10행 미만 제조사는 '기타 제조사' |
| `6-1. 품번 색인 · 교차 참조` | 33–34 | OEM 품번 순, 제품 번호·쪽·COLUMN·BREMBO 품번 |
| `7. 뒤표지` | 35 | 거래 문의 연락처, 홈페이지 QR, 법적 고지 |

쪽 번호·목차·색인의 쪽 번호는 자동으로 매겨집니다. 쪽을 넣거나 빼도 손으로 고칠 필요가 없습니다.

## 반드시 지킬 규칙

1. **B2B 문체.** 본문은 "~합니다", 표·설명은 명사형("~안내", "~발송"). 용어는 다음으로 통일합니다.
   - 1세트(2매), 부가세 포함, 전륜/후륜, 제품 페이지, 기술 자료
   - 회사명은 **주식회사 카리브무역** ("(주)" 쓰지 않음)
   - 가격은 "기준가"로 표시하고, 거래처 공급가는 별도 안내
2. **A/S 유의사항(공통 7개)은 회사가 준 원문입니다.** 표기 교정 외에는 바꾸지 마세요. 바꿔야 하면 사람에게 확인하세요.
   - 이미 반영한 변경: 기준일 "구매일 → 출고일", 3번 항목 분리, 마지막 항목의 당사 귀책 예외 문장.
3. **기술 자료**에는 `data/literature-measurements.js` 에 원문 대조로 등록된 수치만 씁니다.
   - "당사 제품의 시험 결과가 아님" 안내(`NOT_OURS`)는 지우지 마세요.
   - 카오스 가공 제품의 성능을 수치나 우열로 주장하지 마세요 (자체 시험은 계획 단계).
4. **가격·품번·적용 차종은 데이터에서 자동으로 나옵니다.** 문구에 숫자를 직접 적지 말고 `catalog-data.js` 를 기준으로 하세요.
   - 그 파일은 자동 생성본이라 고치면 다음 생성 때 사라집니다.
   - 데이터 오류는 사람에게 알리세요. 예: 670030935 의 외경이 비어 있고 두께가 7로 들어가 있음.
5. **제품 이미지는 대표 이미지입니다.** 품번별 실제 사진은 `photos/` 에 넣고 `photos/photos.js` 에 등록합니다.
6. **홈페이지 파일은 고치지 마세요.** 카탈로그 작업은 `catalog/` 안에서만 합니다.
   - 예외: `catalog-data.js` 등 공용 데이터를 사람이 직접 요청한 경우.
7. 고친 뒤에는 **PDF를 만들어 넘치는 쪽이 없는지 확인**합니다.
   - `build-pdf.js` 가 "주의: 내용이 넘치는 쪽 →"을 출력하면 글을 줄이거나 간격을 조정하세요.
   - 화면에서는 넘치는 쪽에 빨간 테두리가 보입니다.

## 자주 하는 작업

- **문구 수정:** `catalog.js` 에서 해당 쪽 주석을 찾아 HTML 문자열을 고칩니다.
  - 같은 문구가 PDF에 그대로 나오므로 `pdftotext catalog/caribe-catalog.pdf -` 로 확인할 수 있습니다.
- **색 변경:** `catalog.css` 맨 위 `:root` 토큰(`--em` 네이비, `--char` 딥 네이비, `--glow` 강조 등)만 바꿉니다.
- **사람이 화면에서 고친 내용 반영:** `edits.json` 이 있으면 페이지를 열 때 자동으로 적용됩니다. 형식은 `{ "text": { "열쇠": { "html": 고친 내용, "orig": 원래 내용 } } }` 입니다.
  - 열쇠 예: `cover:2`, `card-8K0615301:14`.
  - 원래 내용이 바뀐 칸(데이터 변경)은 적용하지 않습니다.
  - 문구를 영구히 바꾸려면 `catalog.js` 를 고치고 `edits.json` 에서 그 열쇠를 지우세요.
- **PDF 만들기:**
  ```bash
  node catalog/build-pdf.js
  ```
  Playwright 가 필요합니다. 없으면 설치합니다.
  ```bash
  npm i -D playwright
  ```
  ```bash
  npx playwright install chromium
  ```
- **전달용 묶음 다시 만들기:**
  ```bash
  python3 catalog/make-bundle.py
  ```

## 미리보기·수정 페이지 (claude.ai 게시본)

원래 작업자(소유자)가 claude.ai 에 게시한 미리보기 페이지가 있습니다.
- 그 페이지에서 고친 내용은 페이지의 공유 저장소 `edits` 모음에 문서 하나씩 저장됩니다. 각 문서의 필드는 `key`, `html`, `orig` 입니다.
- 소유자나 편집 권한을 받은 사람의 Claude 는 ArtifactData 도구로 그 모음을 읽을 수 있습니다. 읽은 내용을 위 `edits.json` 형식으로 옮긴 뒤 PDF를 만듭니다.
- 게시 페이지는 경로가 저장소와 달라서 `window.CATALOG_ROOT = ""` 로 두고 파일을 평평하게 올립니다. 다시 게시할 때 참고하세요.
